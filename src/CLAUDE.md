# Inbox mod

The mod files agents' items through the inbox tools, delivers the person's answers to each session, and draws the inbox in the Claude Code Sidebar.

- `src/views/` holds the Inbox and File views, which cmod's `mod.views.add` shows beside the session, `src/widgets/` the count above the prompt, and `src/components/` what the Inbox view draws with.
- cmod's `switchSession` resets `memory` at `/clear`, `/resume`, and a fork without rerunning `setup`, so `load` rereads every file at each session start.
- A Problem and a Solution are lists of ideas, each with an optional drawing under it. A report is not: it holds a list of `changes`, each one sentence with an optional drawing and short evidence, plus the Problems left `open`. An agent declares drawings, and `src/completion.ts` checks each one against the code and completes it with `trace api` (at `HEAD` too, for a report's old signatures) and, for each file of a report, `git diff HEAD`, and draws each Mermaid diagram as text with `drawnDiagram` in `src/items/drawings.ts`, before the item is stored. Paths are relative to the item's `project`: the folder the agent's session started in, or the repository it names. The stored drawing is what the code held when the agent filed it. It also refuses a Solution with no drawing.
- Before a filing or a revision is stored, and outside the write queue every answer and note waits on, `rulebookCheck` in `src/tools.ts` runs `rulebook check --stdin-file-path=@inbox/<id>.md` in the mod's folder with the item's Markdown on stdin. Exit 1 prints the refusal on stdout, which fails the tool word for word, and nothing is stored. Exit 0 stores the item, and any text on stdout is a warning the tool's answer carries word for word. When rulebook is missing or exits 2, the item is stored and the tool's answer says why the check did not run. A rule checks an item only when its `paths` name `@inbox/**`, from any folder. `rulebook.config.ts` adds the check of every inbox tool call and of the stored items in a full run.
- Each session delivers its own messages. After every load and every 30 seconds, `deliver` in `src/actions.ts` sends this session a prompt for each answer the person gave and a note for each revision or withdrawal another session made, on the items it subscribes to, and records it in `session.heard` only after the send resolves, which Claude Code does once the prompt enters the conversation. Each item has one mark for its person file's answers and one for its item file's revisions and withdrawal, because a load can read one file before the other. A missing mark starts at `<mod.dataFolder>/delivering-since`, so the first start of a release sends no older answer.
- `src/links.tsx` restyles reply paragraphs and lists that link to an item file, so a click on the link opens the item in the Sidebar. Every tool answer gives the agent that link.
- The shown item, the scope, the kind tab, the selected rows, the folds, the note being written, the text typed into each field, and the file the File view shows live in `session` state, so a reload keeps the person's place.
- The Inbox view shows one scope of items, kept in `session` state: this session's items by default, then this project, then every project. An item belongs to a session that filed it or follows it, and to a project by its repository, which `git rev-parse --git-common-dir` names, so every worktree of a repository is one project.
- The Sidebar's Inbox view draws the list while `session.viewing` names no item in scope, and the item with a back line, `u`, while it does, as a mail app on a phone does. `shownIn` in `src/actions.ts` is that rule. After an answer the next item down the list opens, and after the last one the list. The browser view is a list beside the item, and shows the first item that needs the person when none is chosen.
- Selected rows take Done, which closes only the reports among them, and Mark read. Proposals, choices, and questions stay open, because each needs the person's answer.
- beautiful-mermaid lays branches side by side and has no width limit, and the Sidebar has no horizontal scroll. So `src/components/drawing.tsx` draws the stored boxes only when they fit the view's `columns`, and otherwise an outline it builds from the Mermaid source with beautiful-mermaid's parsers.
- An item's text draws through `Prose` in `src/components/item.tsx`, which draws each list item with a • and its own `Markdown`. A markdown style cannot do it: cmod runs a mod's styles on every mod's `Markdown`, and a style's `Default` draws with the enclosing element's key.
- Claude Code refuses a whole pane that draws two `Markdown`, `Input`, `Select`, `Client`, `Raster`, or `Image` elements with one string key, anywhere in its tree, and blanks the Sidebar. cmod's test kit checks it from 4.3.3. So each such key in an item holds the part's path, and the Answer box's key holds the item id.
- Claude Code 2.1.318 also refuses the whole pane when a `Box`, `Text`, or `Button` has a `hover` with no `Box` with a `key` around it, or the element itself, and no `scope`, because the nearest keyed Box is what the pointer hovers. cmod's test kit checks it from 5.13.0. So each hovered Button sits in its own keyed Box, as the Archive line and each thread link do.
- A cmod view's `focus(key)` moves the keyboard once to the `Input` the view draws with that key, while an `autoFocus` field takes it back each time the Sidebar shows and leaves `x`, `m`, `n`, and `o` typing letters. So no field draws with `autoFocus`. `src/mod.tsx` hands the Inbox view's `focus` through `inboxView` to `ItemView`, and `a` on a question, opening a note, and Comment each set `session.editing` and then call it with the field's key. `focus` rejects a key the view does not draw, so it runs after the state change that draws the field.
- Claude Code keeps what the person typed in an `Input` by its key, and throws it away whenever the drawn `value` changes. While an `Input` has the keyboard, Claude Code 2.1.322 draws its rows in one `Text` with `wrap: "truncate-end"`, which measures all the rows as one line, so a text longer than the field is wide shows as one row cut with "…". It also breaks those rows at the Sidebar pane's width, not the field's. A field without the keyboard wraps at its own width. `session.typed` holds the Answer box's text from its `onInput`, keyed by the `Input`'s key, only so `isWriting` knows the box holds words. It never goes back into `value`, where every keystroke would reset the field. `view` and `forget` in `src/answers.ts` drop it when the Inbox view leaves the item or the answer is sent. An item this session's agent files opens in the Inbox view unless `isWriting`: a field is open, or the shown item's Answer box holds typed text. Then a toast offers it, because moving the view would throw the typed text away.
